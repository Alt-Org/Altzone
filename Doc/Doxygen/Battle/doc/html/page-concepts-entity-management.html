Quantum Entity Management


Entity Manager

The BattleEntityManager handles Quantum Entity management in the game.
Uses {Entity Manager Data} singleton internally to manage {Registered Entities}.

Registered Entities

Quantum Entities are Registered using Register, either individually or as an {Entity Group}, and can be Retrieved and Returned.
Registered Entities are stored offscreen when {OutOfPlay} and are assigned an {Entity ID} for accessing them.
{Compound Entities} have their own RegisterCompound method.

Entities can be Retrieved using Get to be used in the arena. {InPlay}
Entities can be Returned using Return, teleporting them back offscreen. {OutOfPlay}
{Entity Groups} have their own Get and Return methods that take an additional offset argument.

PlayState

The PlayState isn't explicitly tracked in the simulation. This is just the terminology we use and a useful way to think about the state of Entities.
{Registered Entities} have 2 different states, InPlay and OutOfPlay.
When in the arena, a Registered Entity is considered InPlay. When not in the arena, it is considered OutOfPlay.
When OutOfPlay, Registered Entities will be stored offscreen.
The Get and Return methods send a BattlePlayStateUpdate event to update the Unity/View code on the ViewPlayState so it can use and react to that information.

Compound Entity Handling

{Compound Entities} can be made using MakeCompound or RegisterCompound methods.
{Compound Entities} can be moved and teleported using the MoveCompound and TeleportCompound methods.

Note
Registered Compound Entities should only be made using RegisterCompound methods which marks the resulting {Entity ID} as a Compound allowing the Entity Manager to handle it correctly.


Entity ID

Each registered Quantum Entity is assigned an Entity ID by {Entity Manager}.
Each Registered {Compound Entity} is also marked as a Compound.
The BattleEntityID struct is used to represent Entity IDs.


Entity Group

Entities can be registered to {Entity Manager} in Entity Groups.
An Entity Group has one {Entity ID}, and individual Entities within the Group are accessed by using an offset value.


Compound Entities

Quantum Entities can be linked to a Parent Entity to form a Compound which can then be positioned and rotated together as a one unit.
The Parent has a BattleCompoundEntityQComponent which contains a list of Entities that are linked to the Compound Parent.
Compound Entities are made from a CompoundEntityTemplate.

Compound Entities are handled by {Entity Manager}.
Compound Entities can be registered to {Entity Manager} both individually and in groups.
Compound Entities can also be made and used without registering.



EntityManagerData (Quantum Singleton)

The BattleEntityManagerDataQSingleton struct is a Quantum Singleton Component defined in and generated from BattleEntityManagerData.qtn that is used internally by {EntityManager} to manage registered entities.
